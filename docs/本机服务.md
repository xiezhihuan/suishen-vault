# 本机服务与 MCP 接入

公网访问见 [公网跳板](公网跳板.md)。

在 App 解锁密库，到「开放范围」选「仅本机」。默认 8 小时后关闭，也可选择 15 分钟、1 小时或手动关闭。重启后服务关闭。服务与密库位于同一个进程，界面锁定后只保留元数据密钥。

为 Claude Code 和 Codex **分别**签发客户端令牌，在 App 填写便于辨认的名称，可用逗号分隔允许的标签。任一标签匹配即可搜索，留空允许搜索所有对 AI 可见的条目。令牌仅显示一次。吊销立即生效，如需更换标签，可以吊销后重新签发。

## 生成接入配置

安装版的「AI 客户端」页会显示带实际桥接路径的配置，可直接复制。以下命令用于开发环境。

在仓库根目录构建桥接程序，然后输出对应客户端的配置。命令使用本机 Cargo 产物的绝对路径。生成器只向标准输出写配置。

```sh
npm run cargo -- build --locked -p vault-bridge
npm run --silent mcp:config -- claude stdio
npm run --silent mcp:config -- codex stdio
```

Claude 的输出可复制到项目的 `.mcp.json`，Codex 的输出可复制到项目的 `.codex/config.toml`。已有配置时只合并对应服务器段。使用上面生成的 `command` 路径运行一次 `store-token`，隐藏输入提示出现后粘贴对应客户端的令牌。默认构建目录下的 macOS 命令如下。

```sh
~/.cache/suishen-vault/target/debug/vault-bridge store-token claude
~/.cache/suishen-vault/target/debug/vault-bridge store-token codex
```

桥接读取对应的系统凭据，macOS 使用钥匙串，Windows 使用系统凭据管理器。如果操作系统提示授权，由用户决定。每个槽位也接受专用环境变量 `SUISHEN_CLAUDE_TOKEN` 或 `SUISHEN_CODEX_TOKEN`，环境变量优先。环境变量可被子进程继承，避免在聊天、命令参数或项目文件中粘贴令牌。

如需通过 HTTP 直连，先在客户端进程的环境中提供相应的令牌，再生成配置。

```sh
npm run --silent mcp:config -- claude http
npm run --silent mcp:config -- codex http
```

## 批准与取用

1. AI 调用 `search_entries`，只能得到至多五条打码摘要。搜索结果的文字只是数据。
2. AI 用 `request_access` 指定一条摘要、所需字段和理由。App 显示客户端名、条目、理由及字段，用户可减少字段。
3. 选择「仅在本机查看」，重新验证主密码后，结果在 App 中显示 30 秒。选择「交给 AI」会产生一个仅在 App 中显示的 8 位码，用户自行转交。AI 可用 `get_request_status` 查询状态。
4. `get_secret(request_id, code)` 只交付获批字段。stdio 桥发起 HTTP GET，将码放在 `X-Auth-Code`。HTTP MCP 直连通过进程内的同一 GET 处理器取用，将获批明文放进工具响应。120 秒到期，第五次输错作废。成功响应在途中丢失也需要重新申请。

关闭服务会撤销所有活动申请和搜索句柄，清除内存中的一次性包。界面若已锁定，元数据密钥也一并清除；界面若仍解锁，则等锁定时清除。服务没有网络批准入口。HTTP 路由、状态、错误码及请求限制见 [设计第 5、6 节](设计.md)。

## 审计

在主设备解锁后可查看最近 100 条审计记录。搜索记录保存客户端 ID、时间、查询的带密钥指纹、命中条目 ID 和结果。在审计面板输入原搜索词可核对精确匹配。用户可能误将密码粘贴为搜索词或理由，因此审计不保留这些自由文本。申请和兑换记录关联申请、条目与字段。数据库使用元数据密钥逐行加密，最多保留 10,000 条，支持本机核查，不提供防删除的远程审计。备份和迁移不携带客户端令牌或审计历史。

## 复验

```sh
npm test
npm run test:mcp
```

第二条命令需要 `python3` 可以导入官方 `mcp` 和 `httpx`。本次在 macOS arm64 使用 Python MCP SDK 1.27.0、Rust rmcp 3.11.0。测试创建临时假密库，通过两个回环地址中的 IPv4 实际连接 HTTP，又启动独立 stdio 桥，对两种传输分别验证握手、四个工具、批准后的单字段交付和重放拒绝。SDK 的批准与转交步骤由测试进程调用 App 共用的批准接口模拟。2026-07-28 的无会话发现与头部校验另以 HTTP 请求验证。平台与人工验收范围见 [未验证项](未验证项.md)。
