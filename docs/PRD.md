# 随身密库 产品需求

编号约定：`US` 用户故事，`F` 功能，`AC` 验收标准。编号一经发布不复用、不改义；废弃的条目保留编号并注明。`npm test` 会检查编号唯一，以及其他文档和代码引用的编号确实存在。

## 1. 目标与边界

用户总忘记网站账号密码和要记的内容，需要一个随身 App 保存并搜索。Claude、Codex 可以通过 MCP 按描述找到条目，但拿不到全部账号密码；某一条的明文要由用户在 App 上批准，再由用户把授权码交给 AI，AI 凭码通过 GET 接口取得。

平台：macOS 桌面、Windows 桌面、Android，同一时间只用其中一台作主设备。

第一版不做：多端同步、团队共享、浏览器自动填充、iOS、TOTP 生成、附件、密码生成器、从其他密码管理器导入、claude.ai 网页版与 Codex 云端等无法运行本机程序的接入方式（理由见 `docs/设计.md` 第 10 节）。

## 4. 验收标准

"方式"一栏：**自动**＝`npm test` 内的自动化测试；**人工**＝按步骤在真实 App 上操作并记录；**设备**＝需要特定平台或设备，没有条件时写入 `docs/未验证项.md`。

### 4.1 密库与检索

| 编号 | 标准 | 方式 |
|---|---|---|
| AC-VLT-01 | 首次设置时生成恢复密钥，要求用户正确填回随机两组后才能进入密库；恢复密钥不落盘。 | 自动+人工 |
| AC-VLT-02 | 能新增、查看、修改、删除账号、笔记、自定义三类条目；重启并解锁后内容一致。 | 自动+人工 |
| AC-VLT-03 | 删除的条目进入回收站，30 天后或手动清空时物理删除；回收站内条目对 AI 搜索不可见。 | 自动 |
| AC-VLT-04 | App 内可按标题、域名、标签、检索提示搜索，支持中文子串、大小写与全半角归一；1 万条数据下单次搜索不超过 200 毫秒（本机发布版）。 | 自动 |
| AC-VLT-05 | 锁定状态下无法浏览条目列表、查看或复制任何机密字段。 | 自动+人工 |
| AC-VLT-06 | 默认闲置 5 分钟、系统锁屏或休眠时自动锁定。 | 自动+人工 |
| AC-VLT-07 | 主密码少于 10 个字符或属于内置常见弱密码时不能设置。 | 自动 |
| AC-VLT-08 | 保存时若标题、域名、标签或检索提示里包含本条的密码或账号全文（长度不少于 4），拒绝保存并指出字段。 | 自动 |
| AC-VLT-09 | 明文默认遮住，点开后 30 秒自动遮回；复制后 30 秒清除剪贴板，且仅当剪贴板内容仍是本次复制的内容时才清除。 | 自动+人工 |
| AC-VLT-10 | 条目包含"检索提示"和标签输入，界面提示不要在其中写密码。 | 人工 |

### 4.2 密钥与加密

| 编号 | 标准 | 方式 |
|---|---|---|
| AC-KEY-01 | 主密码经 Argon2id（不低于 64 MiB、3 次、并行 4）派生 KEK；读取头部时低于下限或高于上限（1 GiB、20 次、并行 8）的参数被拒绝。 | 自动 |
| AC-KEY-02 | 元数据密钥与机密密钥相互独立随机生成，分别被包裹；只有元数据密钥时，所有机密字段解密均失败。 | 自动 |
| AC-KEY-03 | 每条记录用 XChaCha20-Poly1305 和 24 字节随机 nonce 加密；把密文换到别的条目、字段、修订号或密库时解密失败。 | 自动 |
| AC-KEY-04 | 数据库文件中除设计列明的明文项外，找不到标题、域名、标签、账号、密码、正文。 | 自动 |
| AC-KEY-05 | 锁定后机密密钥不再存在于应用持有的任何对象中；服务运行中只保留元数据密钥；关闭服务并锁定后元数据密钥也清除。 | 自动 |
| AC-KEY-06 | 恢复密钥能独立解开密库并强制设置新主密码；使用后旧恢复密钥失效并生成新的。 | 自动 |
| AC-KEY-07 | 主密码或恢复密钥错误时不泄露任何内容，且两类错误的提示不透露更多信息；连续失败有递增等待。 | 自动 |
| AC-KEY-08 | 修改主密码后旧主密码失效，数据密钥不变，条目无需重加密。 | 自动 |
| AC-KEY-09 | 密钥、明文、授权码类型不实现可打印与序列化，离开作用域时清零。 | 自动 |
| AC-KEY-10 | 只使用设计列出的密码学库，依赖清单中没有自造算法。 | 人工 |

### 4.3 AI 搜索与元数据保护

| 编号 | 标准 | 方式 |
|---|---|---|
| AC-SRC-01 | 搜索最多返回 5 条，每条只含不透明 ID、标题、类型、域名、打码账号，不含其他字段与命中总数。 | 自动 |
| AC-SRC-02 | 查询归一化后，含中日韩字符的少于 2 个有效字符、其余少于 3 个有效字符时拒绝；纯通配符、纯标点、纯停用词拒绝。 | 自动 |
| AC-SRC-03 | 查询只匹配元数据，不匹配账号全文、密码、正文与自定义字段值。 | 自动 |
| AC-SRC-04 | 打码账号不泄露长度，固定 3 个星号；账号短于 4 个字符时全部打码。 | 自动 |
| AC-SRC-05 | 不透明 ID 每次搜索随机生成、绑定客户端、30 分钟失效，另一客户端使用时与不存在的 ID 表现一致。 | 自动 |
| AC-SRC-06 | "对 AI 不可见"的条目不出现在任何搜索结果里；对其已有申请立即失效。 | 自动 |
| AC-SRC-07 | 单客户端搜索每分钟 10 次、每小时 60 次、每天 200 次，超出返回限流错误与重试时间。 | 自动 |
| AC-SRC-08 | 单客户端 24 小时内搜到的不同条目超过 30 个时，该客户端搜索被暂停并在 App 提醒用户，由用户恢复。 | 自动 |
| AC-SRC-09 | 工具清单恰好是搜索、申请、查状态三项（桥接另加取明文一项），没有列出全部、导出、写入工具，也没有资源与提示词接口。 | 自动 |

### 4.4 申请与授权

| 编号 | 标准 | 方式 |
|---|---|---|
| AC-GRT-01 | 申请只针对一条，必须带字段与 1 至 200 字的理由；10 分钟未处理自动过期。 | 自动 |
| AC-GRT-02 | 没有任何网络接口、URL scheme 或命令行能批准申请；只能在主设备 App 内操作。 | 自动+人工 |
| AC-GRT-03 | 批准页显示用户起的客户端名、客户端自称信息（标明未核实）、理由（标明由 AI 提供）、条目、字段；控制字符与双向文本字符被去除。 | 自动+人工 |
| AC-GRT-04 | 每次批准（两种选项都是）都要重新用主密码或生物识别解锁，即使 App 当前已解锁。 | 自动+人工 |
| AC-GRT-05 | 选择"仅在本机查看"时，明文只显示在 App，不产生授权码，AI 查到的状态不含明文，GET 接口拒绝。 | 自动 |
| AC-GRT-06 | 选择"交给 AI"时，界面明确提示明文会进入 AI 服务商的上下文，且可能留在聊天记录里。 | 人工 |
| AC-GRT-07 | 授权码为 8 位 Crockford Base32，由系统安全随机源生成，只显示在 App，不出现在通知、日志、任何网络响应中。 | 自动 |
| AC-GRT-08 | 授权码 120 秒后失效，时钟回拨或休眠不能延长。 | 自动 |
| AC-GRT-09 | 授权码只能成功使用一次；并发 100 个相同请求最多一个成功。 | 自动 |
| AC-GRT-10 | 授权码绑定客户端、申请、条目、字段，任何一项不符都不返回明文。 | 自动 |
| AC-GRT-11 | 错误 5 次后作废，正确的码也不再有效；别的客户端的请求不消耗次数。 | 自动 |
| AC-GRT-12 | 内存中只有授权码的带密钥哈希；比较为常量时间；数据库与磁盘上找不到授权码或其哈希。 | 自动 |
| AC-GRT-13 | 用户可在批准页去掉部分字段，最终只交付勾选的字段。 | 自动 |
| AC-GRT-14 | 条目被修改、删除、设为对 AI 不可见，或客户端被撤销时，相关未完成申请与授权码立即失效。 | 自动 |
| AC-GRT-15 | 单客户端最多 3 个、全局最多 10 个待处理申请；同一条目被拒绝后 5 分钟内不能再申请；连续 3 次被拒后该客户端暂停申请 15 分钟。 | 自动 |
| AC-GRT-16 | 通知只写"有新的授权申请"，不含条目、客户端、理由，也不能在通知上直接批准。 | 自动+人工 |
| AC-GRT-17 | 批准按钮出现后 2 秒内不可点，默认焦点在拒绝。 | 自动+人工 |
| AC-GRT-18 | 状态转移与 `docs/设计.md` 第 5 节一致，终态不可离开。 | 自动 |

### 4.5 GET 明文接口

| 编号 | 标准 | 方式 |
|---|---|---|
| AC-GET-01 | 授权码只从 `X-Auth-Code` 请求头读取；URL 路径或查询串出现授权码时不被接受。 | 自动 |
| AC-GET-02 | 未授权、过期、错误、重复使用、已撤销、仅本机查看时，响应不含任何明文。 | 自动 |
| AC-GET-03 | 该接口的所有响应都带 `Cache-Control: no-store`。 | 自动 |
| AC-GET-04 | `HEAD`、`OPTIONS`、预取与重定向不会消耗授权码；`HEAD` 返回 405。 | 自动 |
| AC-GET-05 | 必须同时有有效的客户端令牌；只有授权码或只有令牌都拿不到明文。 | 自动 |
| AC-GET-06 | 它是 HTTP 接口中唯一返回明文的出口；`/mcp` 的任何响应都不含明文。 | 自动 |
| AC-GET-07 | 错误码与 `docs/设计.md` 第 6 节一致，错误文本不含输入内容。 | 自动 |
