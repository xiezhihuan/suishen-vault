# 桌面端

`apps/client` 是 Tauri 2 应用，前端为 React，规则与系统集成在 Rust。界面按窗口宽度自适应，窄到 360 像素时改为底部导航，供 Android 复用。

## 使用要点

| 操作 | 说明 |
|---|---|
| 首次设置 | 设主密码，抄写 9 组恢复密钥，核对其中随机两组后才写入磁盘。 |
| 解锁与锁定 | 默认 5 分钟没有操作就锁定，可设 1 到 60 分钟。系统锁屏或休眠时总会锁定。服务在运行时，锁定后仍可处理授权申请，但不能浏览密库。 |
| 查看与复制 | 机密默认遮住，点开 30 秒后或窗口失去焦点时遮回。复制由 Rust 直接写剪贴板并标记为敏感，默认 30 秒后清除，且只清除自己写入的内容。 |
| 授权申请 | 焦点默认在「拒绝」，2 秒内不能批准，按回车不会批准。每次批准都要重新输入主密码。授权码显示 120 秒，切换窗口时保留，方便交给 AI；被取用、撤销、作废、关闭服务后立即消失。 |
| 开放范围 | 默认关闭，重启后也关闭。自动关闭默认 8 小时。局域网与公网要等后续任务，界面上不可选。 |
| 托盘与快捷键 | 关闭窗口后留在托盘。`Cmd/Ctrl+Alt+K` 呼出搜索，可在设置里改。退出时关闭服务、锁定、清除自己写入的剪贴板。 |
| 备份、恢复、迁移 | 文件路径只由系统文件对话框给出，界面不能指定。已有密库时不能恢复或导入，避免覆盖。打不开的密库可改名保留，不会删除。 |

新申请不会自动切换页面，以免丢掉没保存的编辑或误点，改用横幅、角标与系统通知提示。

## 代码结构

| 文件 | 内容 |
|---|---|
| `src-tauri/src/state.rs` | 应用状态与规则，不依赖 Tauri，有单独测试 |
| `src-tauri/src/commands.rs` | 主窗口命令，与 `build.rs`、`capabilities/main.json` 三处一致 |
| `src-tauri/src/shell.rs` | 窗口、托盘、快捷键、通知、心跳 |
| `src-tauri/src/clipboard.rs`、`screen.rs` | 剪贴板、系统锁屏检测 |
| `src/pages` | 各页面；`src/test` 为组件测试与前端安全测试 |

`vault-service` 的 `Engine` 与界面共用，伴随应用存续。服务开关与界面锁定互相独立：界面锁定且服务关闭时清除全部密钥，界面锁定而服务运行时只留元数据密钥。

## 前端安全

- CSP 为 `default-src 'none'`，只放行应用自身的脚本与样式，以及 Tauri 的进程内通道。没有内联脚本、`eval`、远程资源、浏览器存储、网络请求，由 `src/test/security.test.js` 检查。
- capability 逐条列出本应用的命令，不开放任何 Tauri 内置能力和插件命令。文件、通知、剪贴板、快捷键只在 Rust 侧调用。
- 窗口只能停留在应用自己的页面，禁止打开新窗口和拖入文件，发布版没有开发者工具，窗口内容受保护。
- 列表与详情只含元数据。机密在点开时逐个取回；编辑时默认「保持原值」，不把机密取到界面。
- 通知文案固定，不含条目、客户端、理由。

环境变量 `SUISHEN_DATA_DIR` 与 `SUISHEN_ALLOW_CAPTURE` 只在调试构建中有效，供自动验收使用临时密库和截图。已实测发布版忽略它们。

## 生物识别为什么没有启用

在本机（macOS 26.2，未签名、ad-hoc）实测：

- 写入带生物识别访问控制的数据保护钥匙串，返回 `-34018`（缺少权限），需要开发者账号签名。
- 用 Secure Enclave 建立带生物识别访问控制的密钥，失败（这台电脑没有配对的 Touch ID 配件）。

按约定不做只有界面判断的假保护，所以只提供主密码。`vault-core` 已支持设备密钥槽，签名条件具备后再接入。Windows Hello 没有设备可验，同样没有接入。

## 打包

```bash
npm run package                                   # 本机平台
npm run package -- x86_64-pc-windows-gnullvm      # 在 macOS 上交叉编译 Windows
```

安装包内含 `vault-bridge`，「AI 客户端」页会给出它的实际路径。

macOS 交叉编译 Windows 没有使用 `cargo-xwin`：它会下载微软 CRT 与 Windows SDK，等于替用户接受微软的许可条款。改用 llvm-mingw（自由许可），产物为 `gnullvm` 目标。准备方法：

```bash
rustup target add x86_64-pc-windows-gnullvm
brew install makensis
mkdir -p ~/.cache/suishen-vault/tools
# 从 https://github.com/mstorsjo/llvm-mingw/releases 下载 ucrt-macos-universal 包，核对校验值后解压到上面的目录
```

本次用的是 20261117 版，SHA-256 为 `98d340bbb8d46b09ad6886ffba88bd9d5415e131c316de48e6bd7647377446aa`。

| 产物 | 状态 |
|---|---|
| `SuishenVault_0.1.0_aarch64.dmg` | 已构建，已在本机运行并走通主流程。ad-hoc 签名，没有公证 |
| `SuishenVault_0.1.0_x64-setup.exe` | **已构建、未在 Windows 上运行**。没有代码签名 |

两个文件放在 `~/.cache/suishen-vault/dist`，不入库。没有公证的 dmg 首次打开会被 macOS 拦下，需由用户在「系统设置 → 隐私与安全性」里选择仍要打开。

`.github/workflows/windows.yml` 在 `windows-latest` 上跑全部检查、打包、安装启动冒烟。它没有推送，也没有运行过。

## 依赖

`cargo audit`（RustSec 1,563 条公告，`52384ab5`）检查 570 个依赖：0 项漏洞，6 项警告。`zbus_names`、`zvariant`、`zvariant_derive`、`glib`、`proc-macro-error` 只在 Linux 依赖树中；`chrono`（已停止维护）在本应用的依赖树中。新增依赖均为 MIT、Apache-2.0、BSD 一类许可，没有 GPL/AGPL。npm 审计接口在当前镜像上不可用，没有执行。
