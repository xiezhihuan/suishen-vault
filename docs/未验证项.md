## 本阶段没有实现

已在 macOS arm64 上验证核心和桌面壳编译，范围及依赖审计见 [密库核心](密库核心.md)。Windows 与 Android 的 SQLite 文件权限、崩溃恢复、迁移与性能仍待实机验证。现有测试以事务中断快照与强杀子进程模拟掉电，未在真实断电或故障存储介质上测试。

本机服务、主窗口批准和授权码兑换的验证记录见 [本机服务](本机服务.md)。macOS 主窗口的操作记录见 [桌面端](桌面端.md)。系统钥匙串授权提示、休眠唤醒和操作系统崩溃转储未验。测试使用临时密库和假数据。Windows/Android 未进行同等构建或实机验证。

局域网 TLS、公网跳板、远程配对与身份接管仍待后续阶段，界面上局域网与公网不可选。批准页没有显示「客户端自称信息」，因为服务目前不收集它。Android 的剪贴板写入会明确报错，等 Android 任务实现。

## 需要用户本人决定的步骤

| 事项 | 命令或步骤 | 没有代办的原因 |
|---|---|---|
| 用 cargo-xwin 生成 MSVC 版 Windows 包 | `cargo install cargo-xwin`，再 `cd apps/client && npm run tauri -- build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis` | 首次运行会下载微软 CRT 与 Windows SDK，等于接受微软许可条款。已改用 llvm-mingw 产出 gnullvm 版 |
| 在 Windows 上验证安装包 | 把 `~/.cache/suishen-vault/dist/SuishenVault_0.1.0_x64-setup.exe` 拷到 Windows 安装，按 [桌面端](桌面端.md) 的验证表走一遍 | 需要 Windows 设备 |
| 运行 Windows 工作流 | 推送仓库后在 GitHub Actions 手动运行 `windows` | 不推送远程 |
| 允许 macOS 通知 | 系统设置 → 通知 → SuishenVault | 系统授权由用户决定 |
| 打开没有公证的应用 | 系统设置 → 隐私与安全性 → 仍要打开 | 系统授权由用户决定 |
| macOS 签名与公证 | 加入 Apple 开发者计划后设置 `APPLE_SIGNING_IDENTITY` 等环境变量再运行 `npm run package` | 需要付费与登录 |
