# 公网跳板

让没有公网 IP 的主设备也能被别处的 AI 用到。跳板 `vault-relay` 跑在你自己的服务器上，前面由 Caddy 或 Nginx 提供 HTTPS。设备主动连出去，不需要在路由器上开端口。

```
AI 电脑 ──HTTPS──▶ Caddy / Nginx ──▶ vault-relay ◀──HTTPS 长连接── 主设备
```

跳板同一时间只认一台主设备，不落盘、不记录正文与来访地址。状态目录里只有设备公钥和没用完的配对码（派生值，不能反推）。

## 两种访问方式

| | 桥接（默认，推荐） | 直连 HTTPS |
|---|---|---|
| AI 那台电脑 | 要装 `vault-bridge` 并配对一次 | 只要填网址和令牌 |
| 加密 | 桥接与设备之间另有一层 TLS 1.3，配对时双方固定对方公钥 | 只有到反向代理的 HTTPS |
| 跳板与反向代理看到什么 | 只有密文：来源地址、时间、流量大小 | **HTTPS 在那里解开：令牌、搜索词、授权码，以及交给 AI 的那条明文** |
| 跳板被攻破 | 换上假设备也没用，公钥对不上，桥接不会发出任何内容 | 可以冒充设备、记下全部内容 |
| 适合 | 平时都用这个 | 服务器完全由你自己控制，且 AI 工具不能运行本机程序 |
| 怎么开 | 开放公网即可用 | 开放公网时另外勾选，默认不勾 |

令牌不通用：仅本机、直连、桥接三种令牌互相用不了，桥接令牌还绑定那台电脑的公钥。没有勾选直连时，跳板不转发直连请求，设备也会再拒绝一次。

两种方式都不改变授权规则：AI 只能搜打码信息、提申请，明文要你在 App 上逐条批准并亲自转交授权码。无论哪种方式，交给 AI 的明文都会进入 AI 服务商的上下文。

公网下限流更严：每客户端搜索 5 次/分、申请 2 次/分、取明文 5 次/分、总计 60 次/分；未认证请求全部来源合计 10 次/分。跳板另按来源限 60 次/分、全局 300 次/分，同时转发 64 个。

## 准备

- 一台有公网 IP 的 Linux 服务器（x86_64 或 arm64），放行 TCP 443；用 Caddy 自动签证书还要放行 80。
- 一个解析到它的域名。下面都写作 `relay.example.com`，换成你的。
- 本仓库的代码。

跳板本身不需要域名证书，也不要把 7470 端口暴露到公网。反向代理须与跳板在同一台机器或同一个容器网络里，因为它们之间没有加密。

## 部署一：Docker Compose + Caddy

```bash
cd deploy/relay
echo 'RELAY_HOST=relay.example.com' > .env
docker compose up -d --build
```

证书由 Caddy 自动申请。检查（没有设备在线时，任何路径都应是同样的 503）：

```bash
curl -i https://relay.example.com/
```

应看到 `503` 与 `{"error":"unavailable"}`。然后生成配对码：

```bash
docker compose exec relay vault-relay pair-code
```

网络不通 Docker Hub 时，先在 Docker 里配好镜像源再构建。

## 部署二：systemd + Nginx（或 Caddy）

在任意装了 Docker 的机器上、仓库根目录，导出静态可执行文件。架构不同时加 `--platform linux/amd64` 或 `linux/arm64`：

```bash
docker build -f deploy/relay/Dockerfile --target bin --output out .
```

也可以在服务器上装好 Rust 后运行 `cargo build --release --locked -p vault-relay`。

把 `out/vault-relay` 和 `deploy/relay` 拷到服务器的同一目录，以管理员身份运行：

<!-- deploy-test:systemd -->
```bash
useradd --system --home-dir /nonexistent --shell /usr/sbin/nologin vault-relay
install -m 755 vault-relay /usr/local/bin/vault-relay
install -m 644 deploy/relay/vault-relay.service /etc/systemd/system/vault-relay.service
echo 'VAULT_RELAY_HOST=relay.example.com' > /etc/vault-relay.env
systemctl daemon-reload
systemctl enable --now vault-relay
systemctl is-active vault-relay
```

Nginx（证书先放到 `/etc/nginx/tls/fullchain.pem` 与 `privkey.pem`，怎么申请由你决定，例如 certbot）：

<!-- deploy-test:nginx -->
```bash
apt-get install -y nginx
install -m 644 deploy/relay/nginx.conf /etc/nginx/conf.d/vault-relay.conf
sed -i 's/relay\.example\.com/relay.example.com/' /etc/nginx/conf.d/vault-relay.conf   # 右边换成你的域名
nginx -t
systemctl restart nginx
```

用 Caddy 代替 Nginx 时，把 `deploy/relay/Caddyfile` 放到 `/etc/caddy/Caddyfile`，给 Caddy 服务设置环境变量 `RELAY_HOST=relay.example.com` 与 `RELAY_UPSTREAM=127.0.0.1:7470`。

生成配对码：

<!-- deploy-test:code -->
```bash
vault-relay pair-code
```

### 反向代理的注意事项

两份配置都已处理好，自己改配置时不要丢掉：

- **关掉访问日志，管住错误日志。** Caddy 默认的错误日志会带上请求头，`Authorization` 会打码，`X-Auth-Code` **不会**，所以 `Caddyfile` 里排除了 `http` 日志（已实测默认配置会泄露）。
- **关掉 Nginx 的缓冲。** 否则直连模式的请求与响应可能写进临时文件。
- **原样传递 `Host`（含端口）、`Upgrade`、`Connection`。** 设备的身份签名绑定主机名，对不上会被拒绝。
- **`X-Forwarded-For` 由代理覆盖或追加。** 跳板只信最后一个值，用来限流，只留在内存里。
- 只开 TLS 1.3。读超时要大于 30 秒，隧道每 10 秒有一次心跳。
- 不要在前面再套 CDN：CDN 也会解开 HTTPS，而且自定义的 `Upgrade` 协议多半不通。

## 在设备上配对

1. 解锁 App，「开放范围」→「公网跳板」，填地址、配对码、主密码。用自签证书的，展开后粘贴 CA 证书。
2. 选「公网」，定好自动关闭时间（默认 1 小时）与是否允许直连。
3. 顶栏显示「已连上跳板」即可用。

配对码 10 分钟有效、只能用一次，线上只传由它算出的证明，截获后不能换到别的设备上用。

**换设备**：在新设备上用新的配对码配对。旧设备的连接当场断开、身份作废，旧设备的 App 会关闭服务并说明原因，但不会删除它的密库（防止被攻破的跳板骗设备自毁）。桥接固定的是旧设备的公钥，要重新配对。

**设备丢了**：在服务器上运行 `vault-relay unpair`（Docker 用 `docker compose exec relay vault-relay unpair`），登记立即清除，该设备一秒左右断开。

## 在 AI 那台电脑上

**桥接**：先在设备上开放公网，再到「AI 客户端 → 公网桥接配对」生成配对串，然后在 AI 那台电脑运行：

```sh
vault-bridge pair claude      # Codex 用 vault-bridge pair codex
```

出现提示后粘贴（输入不显示）。终端会显示指纹，**与 App 上的一致才点确认**。令牌由桥接在加密连接里取走，存进系统凭据。接入配置在 App 的「接入配置」里选「公网桥接」，内容是 `vault-bridge mcp claude remote`。

配对串很长（用了自签 CA）时，终端可能截断，改用管道：`pbpaste | vault-bridge pair claude`。没有系统凭据的无界面服务器，设置环境变量 `SUISHEN_BRIDGE_DIR` 指向一个只有你能读的目录，凭据会存成其中 0600 权限的文件，安全性低于系统凭据。

**直连**：签发令牌时勾选「也用于公网直连」，开放公网时勾选「同时允许直连 HTTPS」。接入配置选「公网直连」。

## 关闭与断线

- 「全部关闭」、切换范围、到期、退出 App、开始迁移：立即断开隧道，申请、授权码、配对全部作废，不再外连。重启 App 后总是关闭。
- 没有登记设备、设备离线、没有开放、没有开直连、路径不存在，跳板的答复逐字相同，看不出有没有设备。设备在线且开了直连时，`401` 与 `503` 的差别会让人知道有设备在线，这避免不了。
- 断网时按 1、2、4……60 秒退避重连。同一次开放期间的断线不作废申请。
- 休眠唤醒后已过自动关闭时间的，立即关闭。

## 管理命令

| 命令 | 作用 |
|---|---|
| `vault-relay pair-code` | 生成配对码，之前没用的作废 |
| `vault-relay status` | 是否登记了设备 |
| `vault-relay unpair` | 清除登记 |

日志只有 `started`、`device_online`、`device_offline`、`device_replaced`、`device_rejected` 这几个固定事件名。

## 不用跳板：ssh -R 或 frp

这两种都是把设备的**本机服务**反向映射到服务器，等同于直连：服务器能看到全部内容，也没有桥接加密、设备身份、接管与公网限流。App 上只开「仅本机」，令牌用仅本机的，**App 的公网开关管不到它们**，停掉 ssh 或 frp 才算关闭公网（或在 App 里全部关闭）。

**ssh -R**：服务器上用 `deploy/relay/nginx-ssh.conf`（它把 `Host` 改成本机服务认得的 `127.0.0.1:47600`），设备上运行：

<!-- deploy-test:ssh -->
```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -R 127.0.0.1:47600:127.0.0.1:47600 tunnel@relay.example.com
```

服务器的 sshd 保持 `GatewayPorts no`，端口只绑回环。建议给 `tunnel` 单独建用户，`authorized_keys` 里加 `restrict,port-forwarding,permitlisten="127.0.0.1:47600"`。

**frp**：服务端 `frps.toml` 设 `bindPort`、`proxyBindAddr = "127.0.0.1"`、`auth.token`；设备端：

```toml
serverAddr = "relay.example.com"
serverPort = 7000
auth.token = "换成你自己的长随机串"
transport.tls.enable = true

[[proxies]]
name = "suishen-vault"
type = "tcp"
localIP = "127.0.0.1"
localPort = 47600
remotePort = 47600
```

前面同样用 `nginx-ssh.conf`。frp 配置没有实测，见 [未验证项](未验证项.md)。

## 复验

```sh
npm run test:relay     # Docker：跳板 + Caddy、跳板 + Nginx，tcpdump 抓包
npm run test:deploy    # Docker：在干净的 Debian 里逐条执行本文的命令
```

`npm test` 里另有不需要 Docker 的同一套场景。两条命令都只用 `localhost` 与假数据，测完删除自己建的容器、卷、网络与镜像。可用 `BUILDX_BUILDER` 指定构建器；`SV_PREBUILT=1` 直接用已有的 `sv-relay-test/*` 测试镜像。

| 场景 | 结果 |
|---|---|
| 桥接全流程，抓包找不到令牌、授权码、明文、条目、路径 | 通过（tcpdump 与进程内全字节录制） |
| 直连对照：同样的抓包能找到明文，说明抓包有效 | 通过 |
| 断网、跳板重启后自动重连 | 通过 |
| 新设备接管，旧设备当场失效，跳板重启后仍失效，配对码不能重用 | 通过 |
| 开关切换、到期关闭、离线答复逐字相同 | 通过 |
| 伪造设备：陌生密钥、冒用公钥、错误配对码、重放、别的跳板骗签、假设备顶替 | 全部拒绝 |
| 跳板与代理的日志、容器文件、状态目录检查 | 通过 |
| 干净 Debian 13 + systemd + Nginx 按文档部署；ssh -R | 通过 |

实现见 `crates/vault-relay`、`crates/vault-tunnel`、`crates/vault-service/src/{tunnel,remote}.rs`、`crates/vault-bridge`。
