# 密库核心

`vault-core` 使用 Rust 和 SQLite，公开入口在 [lib.rs](../crates/vault-core/src/lib.rs)。客户端负责采集输入、显示恢复密钥和批准信息，服务负责把配对令牌映射为可信的客户端 ID。

| 操作 | 调用与约束 |
|---|---|
| 首次设置 | `Setup::begin` 生成密钥，`recovery_key` 交给用户抄存。用 `challenge` 和 `check_answers` 核对两组，最后 `confirm` 创建新文件。主密码与恢复密钥均丢失时无法找回。 |
| 锁定与改密 | `Vault::open` 默认完全锁定。`unlock` 核对加密清单并建立本机索引。`lock(KeepServing)` 清除机密密钥和机密索引，`lock(Full)` 同时清除元数据密钥和临时条目引用。`change_password` 验证旧密码并更换密钥槽。 |
| 找回主密码 | `unlock_with_recovery`、`prepare_password_reset`、`commit_recovery` 依次验证、生成替代凭据、核对后提交。成功时旧主密码、旧恢复密钥和设备解锁槽失效。中途锁定会取消待提交的恢复。 |
| 本机读写 | 用 `ItemDraft` 保存登录、笔记或自定义条目。`get` 与 `search` 要求完全解锁。回收站支持还原、手动清空，活跃设备解锁时清理过期 30 天的记录。密码生成使用系统随机源，TOTP 只供本机查看。 |
| AI 搜索 | `Vault::ai()?.search` 仅匹配元数据。返回最多五条，只有不透明引用、标题、类型、域名、打码账号。引用绑定客户端，有效期 30 分钟。分钟、小时、天滚动窗口分别限 10、60、200 次。24 小时内命中超过 30 个不同条目即暂停，当前批次也不返回。计数加密落盘，恢复调用限本机解锁后使用。 |
| 单次批准 | `reveal_for_grant` 每次重新验证主密码或来自本机钥匙库的设备密钥，检查条目可见性并只解密所选字段。这个进程内入口供主设备批准页使用，不应注册为 MCP 工具。 |
| CSV | `import_csv` 接受 UTF-8（可带 BOM）的 Chrome、Bitwarden、KeePass 和 KeePassXC 表头。有问题的行按序号报告，成功条目一起提交。显示 `ImportReport::delete_prompt()`，有拒绝行时先核对补录。原 CSV 含明文，用户确认后再删除。 |
| 备份 | `export_backup` 与 `restore_backup` 使用独立包头和认证加密，恢复需要主密码或恢复密钥。恢复校验全部条目并写到新路径，拒绝覆盖原库。 |
| 换设备 | `begin_migration` 让旧设备进入只读状态，`import_migration` 要求迁移码及密库凭据，验证并回读新库后才返回完成码。用 `confirm_migration` 停用旧库后，界面应提示清除本机副本。设备解锁槽与客户端配额不迁移。 |

没有中心服务器时，程序无法禁止手工复制备份、密库或带迁移码的迁移包，也无法撤销已复制的旧快照。旧设备完成迁移后会拒绝解锁。公网跳板只承认一个设备身份，见 [公网跳板](公网跳板.md)。

## 验证记录

2026-11-23 在 macOS arm64 使用 Rust 1.95.0。以下命令复用仓库的 Cargo 缓存。

```bash
npm test
npm run cargo -- clippy --release -p vault-core --all-targets --locked -- -D warnings
npm run cargo -- audit
```

核心的单元、集成和属性测试覆盖恢复轮换、锁定、两套搜索的可见范围、重启后的限流、CSV 和迁移。用 RFC 9106 及 Argon2 参考实现向量检查 KDF，用 XChaCha 草案附录 A.3.1 检查 AEAD。故障测试交换条目和字段密文、回滚单行、使用错误口令、降低 KDF 参数、截取未提交事务的文件并强杀写入进程。字节扫描在实际数据库、备份与迁移包里查找特征假密码、账号、正文、标题等标记。

发布版性能测试导入 10,000 条假记录并重新打开，计入解锁后的首次查询。一次独立运行首次查询 3.48 ms，一组本机与 AI 查询中最慢 38.67 ms，门槛为 200 ms。该结果仅适用于这台机器和这组查询。
